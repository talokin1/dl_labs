# ЛР1. backpropagation

Реалізовано мережу `4 → 8 → 3`: два афінні шари та ReLU. NumPy рахує forward і backward вручну, PyTorch використовується тільки як еталон. Ваги не оновлюються: мета роботи — перевірити градієнти до навчання.

## Запуск

Потрібен `uv`. Із теки `lab1/`:

```bash
uv run --python 3.12 --with-requirements requirements.txt python main.py
uv run --python 3.12 --with-requirements requirements.txt python main.py --bug
```

Перший запуск перевіряє правильний backward, другий — backward без ділення на 105. У режимі `--bug` непройдені перевірки градієнтів означають, що помилку виявлено. За замовчуванням працює правильна реалізація.

## Дані та ініціалізація

Iris: 150 об’єктів, 4 ознаки, 3 класи. Для класів 0, 1, 2 послідовно перемішано індекси через `default_rng(0)`: перші 35 у train, решта 15 у test. Отримано 105/45 об’єктів без перетину.

Стандартизація: $x'_{ij}=(x_{ij}-\mu_j)/\sigma_j$. Статистики лише з train, `ddof=0`, тобто знаменник дисперсії дорівнює 105. Для test застосовано ті самі статистики.

Новий `default_rng(0)` генерує спочатку $W_1$, потім $W_2$. Стандартні відхилення: $\sqrt{2/4}$ для He та $\sqrt{2/(8+3)}$ для Xavier. Зміщення нульові. Обчислення — `float64`, мітки класів та індекси — цілі числа.

## Forward і функція втрат

$$Z_1=XW_1+b_1,\quad A_1=\max(0,Z_1),\quad Z_2=A_1W_2+b_2.$$

Для кожного об’єкта $m_i=\max_k Z_{2,ik}$, $S_{ik}=Z_{2,ik}-m_i$:

$$\log P_{ik}=S_{ik}-\log\sum_j e^{S_{ij}},\qquad L=-\frac1N\sum_i\log P_{i,y_i}.$$

Віднімання максимуму не змінює softmax, але робить всі аргументи експоненти недодатними. Обчислюється саме log-softmax: `log(softmax)` може дати `log(0)` через underflow.

## Backward

Нехай $Y$ — one-hot мітки, $G_2=\partial L/\partial Z_2$. Для одного об’єкта $\ell_i=-Z_{2,i,y_i}+\log\sum_k e^{Z_{2,ik}}$, тому $\partial\ell_i/\partial Z_{2,ik}=P_{ik}-Y_{ik}$. Усереднення за об’єктами додає множник $1/N$:

$$G_2=(P-Y)/N.$$

Для $Z=AW+b$ маємо $dZ=dA\,W+A\,dW+db$. Підстановка у $dL=\langle G,dZ\rangle$ дає $\partial L/\partial W=A^TG$, $\partial L/\partial A=GW^T$; внески у спільний bias сумуються за об’єктами. Отже:

$$\frac{\partial L}{\partial W_2}=A_1^TG_2,\quad \frac{\partial L}{\partial b_2}=\sum_i G_{2,i:},\quad \frac{\partial L}{\partial A_1}=G_2W_2^T.$$

$$G_1=(G_2W_2^T)\odot\mathbf1[Z_1>0],\quad \frac{\partial L}{\partial W_1}=X^TG_1,\quad \frac{\partial L}{\partial b_1}=\sum_iG_{1,i:}.$$

У нулі ReLU недиференційовна; використано похідну 0, як у PyTorch. One-hot матриця не створюється: від імовірності правильного класу віднімається 1. Ділення на $N$ виконується рівно один раз.

| Масив | Shape |
|---|---|
| $X$ | $(105,4)$ |
| $y$ | $(105,)$ |
| $W_1$, $\partial L/\partial W_1$ | $(4,8)$ |
| $b_1$, $\partial L/\partial b_1$ | $(8,)$ |
| $Z_1,A_1,G_1,\partial L/\partial A_1$ | $(105,8)$ |
| $W_2$, $\partial L/\partial W_2$ | $(8,3)$ |
| $b_2$, $\partial L/\partial b_2$ | $(3,)$ |
| $Z_2,P,Y,G_2$ | $(105,3)$ |
| $L$ | скаляр |

У cache зберігаються $X$ для $dW_1$, $Z_1$ для маски ReLU, $A_1$ для $dW_2$. Імовірності повертаються з функції втрат, ваги $W_2$ беруться з параметрів. Оновлень ваг між forward і backward немає.

## Перевірки

У `nn.Linear` ваги зберігаються як `(out, in)`, тому при копіюванні та порівнянні градієнтів використовується транспонування. Порівнюються всі елементи: максимум абсолютних різниць має бути $\le10^{-12}$. Окремо перевіряється скінченність значень.

Чисельна похідна: $g_{num}=[L(\theta+\varepsilon)-L(\theta-\varepsilon)]/(2\varepsilon)$, $\varepsilon=10^{-6}$. Змінюється один елемент, початкове значення відновлюється через `finally`. Критерій: $|g_{num}-g_{manual}|\le10^{-7}$. Додатково перевірено, чи змінилася маска ReLU між двома збуреннями.

## Дослід із помилкою

Прогноз перед запуском: Без /N втрата не зміниться. Кожен ненульовий градієнт стане у 105 разів більшим. Порівняння втрати пройде, перевірки градієнтів PyTorch і чисельними різницями виявлять помилку. Нульові градієнти залишаться нульовими.

NumPy loss: `1.4562007801142816`. PyTorch loss: `1.4562007801142818`.

| Величина | Максимальна абсолютна різниця | Пройдено |
|---|---:|:---:|
| loss | 2.220446049250e-16 | так |
| W1 | 1.851813798076e+01 | ні |
| b1 | 1.564109394848e+01 | ні |
| W2 | 3.419343293963e+01 | ні |
| b2 | 1.119708618182e+01 | ні |

| Параметр | backward | Чисельна похідна | Абсолютна різниця | Пройдено |
|---|---:|---:|---:|:---:|
| W1[0, 0] | -2.09161935470831 | -0.019920184390898 | 2.071699170317e+00 | ні |
| b1[0] | -7.4094417163599 | -0.0705661116207068 | 7.338875604739e+00 | ні |

Прогноз підтвердився. Максимальне відхилення від рівності `g_bug = 105 * g_correct` становить `7.105e-15`. Це похибка округлення. Чисельні похідні залишилися такими самими, бо функція втрат не змінювалася. Після досліду правильний backward повторно пройшов звірку з PyTorch.

## Висновок

Ручні градієнти узгоджуються з autograd для всіх параметрів та з центральною різницею для чотирьох заданих елементів. Пропуск `/N` виявили обидва методи, хоча значення loss залишилося правильним. Перевірка лише forward не перевіряє backward.
